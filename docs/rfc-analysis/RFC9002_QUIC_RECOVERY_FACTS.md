### 9002 section 6.1-6.2 - RFC 9002 — Loss Detection: Acknowledgment-Based Detection and Probe Timeout

| ID | Level | Requirement (scope) | RFC 9002 verbatim | Impl check / status |
|----|-------|---------------------|-------------------|---------------------|
| `6.1-6.2-1` | informative | Loss detection state is kept separately per packet number space, whereas RTT measurement and congestion control are per-path properties shared across spaces. <br>_(endpoint [CLIENT])_ | Loss detection is separate per packet number space, unlike RTT measurement and congestion control | quic/loss.go: verify per-PN-space largest-acked/loss-time/sent-packet maps, while quic/rtt.go and quic/cc.go hold one shared instance per connection. |
| `6.1-6.2-2` | informative | A packet may be declared lost only if it is unacknowledged, in flight, and was sent before a packet that has been acknowledged. <br>_(sender [CLIENT])_ | The packet is unacknowledged, in flight, and was sent prior to an acknowledged packet. | quic/loss.go: detect-lost path must gate on packet number < largest acked in the same PN space and on in-flight status. |
| `6.1-6.2-3` | informative | The second loss condition is a disjunction: sent kPacketThreshold packets before an acknowledged packet, OR sent longer ago than the time threshold. <br>_(sender [CLIENT])_ | The packet was sent kPacketThreshold packets before an acknowledged packet (Section 6.1.1), or it was sent long enough in the past | quic/loss.go: confirm loss check is (largestAcked - pn >= kPacketThreshold) \|\| (sentTime <= now - lossDelay), not a conjunction. |
| `6.1-6.2-4` | MAY | Implementations with adaptive time thresholds may start with smaller initial reordering thresholds to minimize recovery latency. <br>_(sender [CLIENT])_ | Implementations with adaptive time thresholds MAY choose to start with smaller initial reordering thresholds to minimize recovery latency. | quic/loss.go: fixed thresholds are conformant; only relevant if adaptive thresholds are ever added. |
| `6.1-6.2-5` | RECOMMENDED | The recommended initial packet reordering threshold kPacketThreshold is 3. <br>_(sender [CLIENT])_ | The RECOMMENDED initial value for the packet reordering threshold (kPacketThreshold) is 3 | quic/loss.go: check kPacketThreshold constant equals 3. |
